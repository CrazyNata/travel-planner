# Ramingo iOS — отчет полного QA-аудита

Дата аудита: 2026-09-18  
Область: только нативное приложение `ios/`. Web и Android в рамках этого аудита не изменялись.

## Итог

Приложение нельзя считать полностью проверенным и готовым к релизу. Supabase Auth API и read-only backend-запросы отвечают, iOS Simulator build собирается и запускается. Но текущий авторизованный UI-прогон не проходит: приложение остаётся на splash, затем возвращается на экран входа, поэтому до маршрута, фильтров и формы создания поездки тесты не доходят.

Найдены подтвержденные дефекты в текущей iOS-реализации, один воспроизводимый дефект API-контракта и несколько блокеров, которые нельзя закрыть только статическим анализом.

## Что было проверено

- Вход в Supabase с выделенной QA-учетной записью: успешно; пароль в файлы, логи и отчет не записывался.
- Чтение данных аккаунта: 9 поездок прочитаны; существующие поездки не изменялись и не удалялись.
- Backend catalog для sight, restaurant, accommodation, pet shop и pet vet: ответы получены, для проверенных городов вернулись записи с рейтингами и фотографиями.
- Погода Open-Meteo: ответ получен.
- Курсы Frankfurter: ответ получен для EUR/USD/CZK.
- Расчет маршрута Valhalla: ответ получен с длиной маршрута.
- Контракт создания поездки и patch-операций: создание, изменение основных полей, массивов и отдельного элемента с новой ревизией прошли.
- Временная тестовая поездка для mutation-проверки была удалена; после очистки она не находится.
- Исторический GitHub Actions run [35350152001](https://github.com/CrazyNata/travel-planner/actions/runs/35350152001), commit `e6ac3fe`, действительно показал авторизованный Home и запрос геолокации.
- Актуальный launch-only run [35373190568](https://github.com/CrazyNata/travel-planner/actions/runs/35373190568), commit `df74580`, собирается и запускает приложение.
- Актуальный авторизованный UI run [35373697869](https://github.com/CrazyNata/travel-planner/actions/runs/35373697869), commit `df74580`, завершился с `Executed 2 tests, with 2 failures`: оба теста упали на ожидании `Главная`.

## Ограничения результата

1. Текущий iOS workflow проверил commit `df74580`; незакоммиченные изменения в Web/Android/design-reference/tmp не включались в iOS-коммит и не изменялись в этой проверке.
2. На Windows нет локального Xcode/iOS Simulator; native UI проверяется удалённым macOS job.
3. Текущий авторизованный UI-прогон не проходит bootstrap, поэтому сценарии создания поездки, фильтров, карточек, редактирования, фотографий, уведомлений, permissions и настроек остаются непроверенными.

## Новые дефекты

### QA-IOS-028 — Карандаш маршрута открывает общий редактор вместо выбранного переезда

- Приоритет: P1
- Статус: `FIXED_LOCALLY_UNVERIFIED`, native runtime требует UI-проверки.
- Шаги: открыть поездку → «Маршрут» → нажать карандаш на конкретной карточке переезда.
- Ожидание: открывается редактирование именно выбранного переезда с его текущим временем заселения/данными.
- Исправление: карточка передает выбранный `RouteLeg` в отдельный редактор времени заселения; сохранение вызывает существующий `updateRouteLegDetails` и сохраняет остальные поля переезда.
- Доказательство: `ios/Ramingo/UI/TripDetailView.swift` — `openRouteCheckInEditor`, `RouteCheckInEditorSheet`, `saveRouteCheckIn`.

### QA-IOS-029 — Карандаш достопримечательности также не выбирает конкретный элемент

- Приоритет: P1
- Статус: `FIXED_LOCALLY_UNVERIFIED`, native runtime требует UI-проверки.
- Исправление: карточка передает ID выбранной достопримечательности, а `TripEditorView` открывает именно этот `EditableItem`.
- Доказательство: `ios/Ramingo/UI/TripDetailView.swift` и `ios/Ramingo/UI/TripEditorView.swift` — `initialItemID`/`openInitialItemIfNeeded`.
- Риск: пользователь не может предсказуемо изменить именно нажатую карточку; это не соответствует Android-сценарию редактирования элемента.

### QA-IOS-030 — На карточке ресторана нет действия редактирования

- Приоритет: P1
- Статус: `FIXED_LOCALLY_UNVERIFIED`, native runtime требует UI-проверки.
- Исправление: карточка получила pencil с ID ресторана; «Подробнее» открывает локальный details-sheet, откуда также доступно редактирование.
- Доказательство: `ios/Ramingo/UI/TripDetailView.swift` — `AndroidRestaurantCard`, `IOSRestaurantDetailsSheet`.
- Риск: нельзя изменить конкретный ресторан из его карточки так, как это предусмотрено Android.

### QA-IOS-031 — Конфликт ревизии не возвращается, запрос зависает

- Приоритет: P1
- Статус: `REPRODUCED_API`, нужен server-log для определения причины зависания.
- Шаги проверки: создать временную поездку; выполнить patch с `expected_revision=0`; повторить patch с тем же устаревшим `expected_revision=0`.
- Ожидание: быстрый контролируемый conflict/error без изменения данных.
- Факт: второй вызов `patch_trip_payload` не вернул ответ за 10 секунд и был прерван по timeout. Первый patch с новой ревизией работал.
- Доказательство клиента: `ios/Ramingo/Networking/TripRepository.swift:297-307` вызывает `patch_trip_payload` с `p_expected_revision`.
- Риск: при одновременном редактировании поездки iOS может зависнуть на сохранении вместо показа конфликта.
- Примечание: тестовая строка после проверки удалена; существующие поездки не затронуты.
- Клиентская защита: обычные iOS-запросы теперь имеют 15-секундный timeout и показывают контролируемую ошибку. Причина зависания серверного RPC по-прежнему не исправлена.

### QA-IOS-036 — В разделе маршрута отсутствовала доступная кнопка добавления переезда

- Приоритет: P1
- Статус: `FIXED_LOCALLY_UNVERIFIED`.
- Исправление: в iOS-раздел добавлена кнопка «Добавить переезд» и форма с городами, датой, временем, картой, расстоянием и заметками; сохранение использует существующий `addRouteLeg`.

### QA-IOS-037 — Карточка ресторана не меняла статус и не открывала локальные подробности

- Приоритет: P1
- Статус: `FIXED_LOCALLY_UNVERIFIED`.
- Исправление: добавлено переключение статусов через существующий `updateTripArrayItem`, отдельный details-sheet и переход к редактированию выбранной записи.

### QA-IOS-032 — CI не проходит полный авторизованный пользовательский сценарий

- Приоритет: P1 release QA blocker
- Статус: `OPEN_AUTH_UI_BLOCKED`.
- Факт: workflow получает временные QA-токены через Supabase Auth и запускает два native XCTest, но приложение не доходит до Home. Интерактивные tap-сценарии и CRUD после входа поэтому не выполняются.
- Доказательство: `.github/workflows/ios-build.yml`; авторизованный run [35373697869](https://github.com/CrazyNata/travel-planner/actions/runs/35373697869) — два падения на ожидании `Главная`.
- Результат: green launch-only CI означает только «сборка запускается»; авторизованный UI run сейчас красный и блокирует дальнейшее покрытие.

### QA-IOS-033 — Фильтры ресторанов основаны на свободном тексте заметки

- Приоритет: P1
- Статус: `CONFIRMED_BY_CODE`, native runtime/result parity требует отдельного сценария.
- Факт: тип заведения и признаки `Бар`, `Кафе`, `С собакой`, `Веган`, `Бронь` вычисляются через поиск слов в `restaurant.note`; отдельное структурированное поле типа/признаков в фильтре не используется.
- Доказательство: `ios/Ramingo/UI/TripDetailView.swift:1283-1305`.
- Риск: одна и та же запись может попасть не в тот фильтр или исчезнуть из него из-за языка, формулировки или пустой заметки. В Android логика использует тот же уязвимый подход, поэтому нужна сверка поведения, а не предположение о parity.

### QA-IOS-034 — Записи без координат проходят фильтр радиуса питомцев

- Приоритет: P1
- Статус: `CONFIRMED_BY_CODE`, native runtime требует UI-проверки.
- Факт: в iOS-логике фильтра питомцев отсутствие координат возвращает `true`, то есть запись считается подходящей для любого выбранного радиуса.
- Риск: фильтр 1/5/10/25 км может показывать места, расстояние до которых неизвестно; пользователь получает неверный результат радиусного поиска.
- Доказательство: `ios/Ramingo/UI/TripDetailView.swift:1860-1967`.

### QA-IOS-035 — Текущие iOS-изменения не подтверждены полной авторизованной проверкой

- Приоритет: P1 release QA blocker
- Статус: `OPEN_AUTH_RUNTIME_BLOCKED`.
- Факт: launch-only run [35373190568](https://github.com/CrazyNata/travel-planner/actions/runs/35373190568) собрал commit `df74580`, а авторизованный UI run [35373697869](https://github.com/CrazyNata/travel-planner/actions/runs/35373697869) дошёл до XCTest и завершился двумя падениями на `Главная`.
- Ограничение: сборка подтверждена, но авторизованный runtime и интерактивные сценарии текущего iOS HEAD не подтверждены.

### QA-IOS-038 — Авторизованный iOS bootstrap возвращает приложение на экран входа

- Приоритет: P0 release blocker
- Статус: `REPRODUCED_CI`
- Шаги: собрать Debug Simulator app; получить live Supabase session; запустить приложение с access/refresh token и реальным `tripID`; открыть XCTest-сценарии.
- Ожидание: после bootstrap открывается «Главная» выбранной поездки.
- Факт: callback/Auth API проходит, реальный trip ID получен, оба XCTest запускаются, но приложение остаётся на splash и затем показывает экран входа. `testAuthenticatedTripSectionsAndFilters` и `testCreateTripFormValidationWithoutSaving` падают на первом ожидании `Главная`.
- Доказательство: run [35373697869](https://github.com/CrazyNata/travel-planner/actions/runs/35373697869), UI log: `Executed 2 tests, with 2 failures`; видеокадр после ожидания показывает AuthView.
- Техническая граница: `AppModel.bootstrap()` сбрасывает `session` при любой ошибке `establishSession()` или `finishAuthenticatedBootstrap()`, поэтому UI скрывает исходную ошибку. Точный запрос, который сбрасывает сессию, ещё не локализован.
- Риск: весь авторизованный iOS-функционал недоступен для честной проверки, пока не устранён этот блокер.

## Что пока не закрыто как баг или pass

Следующие пункты требуют интерактивного запуска iOS и поэтому оставлены `QA_PENDING`, а не выданы за проверенные:

- вход/выход и восстановление сессии в native UI;
- создание поездки через форму, сохранение после перезапуска и сохранение всех соседних данных;
- редактирование маршрута, достопримечательностей, ресторанов, жилья, бюджета, участников и фото;
- фильтры городов, статусов, типов, особенностей, цены и рейтинга на реальных карточках;
- каталог жилья и добавление из каталога;
- Google/Apple login, регистрация с подтверждением email и recovery deep link;
- permissions для карты, геолокации и PhotosPicker;
- уведомление с переходом в конкретную поездку;
- удаление аккаунта и очистка сессии;
- холодный запуск, offline/error states, rotation/разные iPhone sizes и accessibility;
- подписанный Release archive, TestFlight и App Store review metadata.
